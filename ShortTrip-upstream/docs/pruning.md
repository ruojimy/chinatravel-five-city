# 提前剪枝规则

生产源码位于当前仓库。离线测试位于 tests 和 experiments/c_only，历史实验结果单独保存。

## 触发位置

- 去程、返程候选先执行确定性过滤，再执行原有约束通过数排序及早去晚回排序。
- 固定交通、酒店组合进入 DFS 前，以及每次递归进入时，检查不可恢复的违规。
- C 组在空行程入口检查必需三餐的乐观营业时间可行性及费用下界。
- 完整行程仍执行原有完整校验、C 组审核和软约束评分，目标仍为20候选。

## 确定性过滤

- `intercity_transport`：去程不能使用禁用类型；两程确定后必须满足完整类型集合。
- `train_type`：已选火车必须满足字头限制；只选飞机但要求火车字头的完整组合不可行。
- `return_start_time`：按原约束的严格/含等号比较返程出发时间。
- 已选酒店的房型、明确房间数和价格限制；已发生活动的餐费、票数、车数限制。
- 市内交通按原验证器的主要方式判断，允许地铁的接驳步行。模型只决定顺序，不能遗漏
  其他硬约束允许的方式。赶不上酒店或返程的判断要尝试所有允许方式；未知路线信息不证明无解。

## 费用下界

合并已选去返程、已选酒店应住夜数、已经发生的活动和全部市内交通费用，预留费用与
实际费用取最大值，避免重复计费。跨午夜去程占用的夜晚不预留酒店费用。
删除原固定“每人每天剩余100元”门槛，以及未计市内交通的重复旧预算检查。
价格使用与实际活动相同的整数计费语义。

C 组另加必需餐饮最低费用。营业时间检查假设零通勤、允许复用餐厅，各餐独立选最低价；
真实有酒店住宿的次日保留免费08:00早餐。未知数据不作为无解依据。这些是乐观必要条件，
通过不保证真实路线可行。没有增加车站缓冲、景点时长或三餐窗口限制。

## 保留的分支

尚未到访的必去景点、餐厅、类型和未出现的要求交通类型，不能仅因当前缺少而判为失败。
自定义 Python 约束不在部分行程上直接执行，仍由完整校验检查。

## 诊断

日志 `PRUNE` 记录规则、原约束及上下文。每种规则保留前三个示例，累计次数不截断。
最终 soft selection JSON 包含 `prune_counts`、`prune_examples`。
三餐失败细分为日期、具体餐次截止、景点后餐厅/接驳不可行、完整C审核等原因。

## 验证

新增27项剪枝测试、原项目99项测试、C规则43项测试均通过，发布前测试直接导入当前生产源码。
历史4个超时案例仅进行固定选择的离线回放：easy_1 错误的火车+飞机组合可在DFS前拒绝；
其他3个组合通过乐观检查，尚未证明无解。没有重新运行完整十例，旧批次继续保留原快照。
