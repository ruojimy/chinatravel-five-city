## 怎么补的

1. **本地原始响应回填（不联网）**
   - 景点营业时间：从 `raw_bulk` 的高德 `business.opentime_week` 解析，按同名匹配。
   - 地铁 line：用 `transportation/subways.json` 的线路-站点表 join，唯一命中才写。
   - 餐厅菜系/时间：同名匹配高德/百度原始 POI。
2. **auto 子代理补采（允许权威清单以外来源）**
   - 住宿价格：Trip.com / 携程详情页 JSON-LD `priceRange`，40 + 3 家。
   - 餐饮/景点：携程美食/景点页、高德/百度 POI。

   - 151 条 `00:00–24:00` 的景点：endtime 归一为 `23:59`（`24:00` 不是合法 HH:MM），逐条记 `24h_close_normalized_24:00_to_23:59`。

## v7 修正（2026-11-09 17:55）：只有“已抓页且确实无价”才允许估

### 修正原因

首版 v7 把“没搜过”的酒店也按最近邻填了估价（687 条），这不符合“实在找不到才凑”的要求。已回退：**未实际搜索的酒店一律留空**，估价只用于已抓到详情页但没有价格的酒店。

### 规则

- 已有真实 price/numbed 一律不覆盖。
- 估价前置条件：该酒店有 **Trip.com 详情页抓取记录（`run_log.stage=done`）** 且页面无价格；估价条目必须带 `attempt_ref`（run_log + hotel_id）。

- `numbed` 按用户口径默认 1（有主房型床数则用主房型），这部分不依赖搜索。
