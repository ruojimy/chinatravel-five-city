# 独立数值与引文绑定审计（2026-11-01）

## 范围与方法

只读检查 `strict_independent_verifier._value_occurs`，以隔离 Python 3.13.12 fixture 调用该 helper。未联网、未改源码。测试金额统一为 claim value `100` 或 `200`、unit `CNY`，并检查负号、千分位、范围标点、日期与单位。

## 复现：不同金额可通过未识别的数字分组符绑定

当前实现已拦截 ASCII 逗号 `,`、中文逗号 `，`、小数点以及常见 ASCII/Unicode 减号 `-`、`−`、`－` 和加号。但金额正则的左边界只排除 `0123456789 . , ， + - − － ＋`。其余分组符可让它把较大金额的后缀识别成独立金额。实际结果：

| Quote | Claim `100` 是否绑定 | 问题 |
|---|---:|---|
| `1’100元` | true | U+2019 分组撇号；把 1100 错绑成 100 |
| `1'100元` | true | ASCII 撇号分组 |
| `1_100元` | true | 下划线分组 |
| `1٬100元` | true | U+066C 阿拉伯千分位 |
| `1 100元` | true | U+202F 窄不换行空格分组 |

对照：`1,100元` 与 `1，100元` 均被拒绝。这确认是分组标点覆盖不全造成的数值子串边界错误，不只是格式不兼容。

## 复现：负号与范围标点覆盖不全

常见 `-100元`、`−100元`、`－100元`、`+100元`、`＋100元` 均拒绝绑定正 `100`。但以下明确负数或范围写法会被当作正金额：

| Quote | Claim | 结果 |
|---|---:|---|
| `–100元` (U+2013 en dash) | `100` | true |
| `—100元` (U+2014 em dash) | `100` | true |
| `‐100元` (U+2010 hyphen) | `100` | true |
| `﹣100元` (U+FE63 small hyphen-minus) | `100` | true |
| `负100元` / `负数100元` | `100` | true |
| `亏损100元` | `100` | true |
| `100–200元` / `100—200元` | `200` | true |
| `100~200元` / `100～200元` / `100 至 200元` | `200` | true |
| `100/200元` / `100、200元` | `200` | true |

范围表达里只给第二端附货币单位时，正则只找到结尾的一个 currency-marked token，因此“只有一个金额”的检查没有阻止将范围当成固定 200 元。负面语义也存在前缀形式：`退款100元`、`退还100元` 和 `亏损100元` 都能绑定正 `100`；后缀形式 `100元退款` 因 Unicode `\w` 边界被拒绝，前后不一致。

## 日期、空格、多金额和单位对照

- `日期2026-11-01：费用100元` 绑定 `100`，不绑定日期数字 `2026`；这项有标点分隔的常见场景表现合理。
- `日期2026-11-01，100元` 被拒绝，因为千位分组检测把“日期末尾逗号金额”整体当成可疑分组。这是保守误拒绝，可作为修复分组规则时的兼容回归样例。
- `100元/200元`、`100元（原价200元）`、`100元或200元` 因出现两个货币 token 而全部拒绝，行为正确。
- `100 元`、`100\t元`、`100\n元`、`100人民币`、`100 CNY` 可绑定；`CNY 100`、`CNY100`、`人民币100`、`100块`、`100元整`、`100.00元` 对 claim `100` 被拒绝。这些是当前字面格式/单位覆盖的兼容性限制，不是误绑正金额。
- `100元/晚` 可绑定，说明修复不能把所有斜杠都一概禁用；应只拒绝金额 token 内部含数字的范围/比值形式，同时保留金额单位之后的 `/晚`、`/人`。

## 建议的保守修复

1. 先提取完整数字 token，再解析；禁止只匹配它的末尾。token 边界应涵盖所有 Unicode 数字、标点和分组字符。对无法无歧义规范化的分组（撇号、下划线、U+066C、窄空格等）直接拒绝，不要尝试截取。
2. 将常见 Unicode 减号/连字符全量纳入负号识别，并拒绝 `负数?`、`亏损` 等紧邻金额的负向表达。对退款、退还、返还等方向词采取字段无关的 fail-closed 处理，直到调用方将 claim field 传入并能按“费用/退款”语义分别判断。
3. 将金额范围检查覆盖 `–`、`—`、`~`、`～`、`至`、`、` 等连接两组数字且只在末尾标货币单位的模式；仍允许 `100元/晚` 这类金额之后的计价单位。
4. 回归测试应至少包含上述误绑例，以及日期后的中文逗号金额、`100元/晚`、多个独立金额和负号带空格等不应误拒绝/必须拒绝案例。

## 结论

最新收紧已修复常见逗号分组和常见正负号，但仍可复现两类误绑定：非 ASCII 常见分组符导致 `1’100元 → 100`，以及未覆盖的 Unicode 短横/范围标点或中文负向前缀导致负数/范围端点绑定为正的精确金额。应先修完整数字 token 的边界，再考虑语义 review；当前语义 review 的字面 binding 不能弥补机械 gate 把错误金额提取为通过的风险。
